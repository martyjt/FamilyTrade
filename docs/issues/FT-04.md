## Scope

- Implement the small private-user login/session flow selected in the architecture review; no public registration or billing.
- Represent independent broker accounts under a user, and associate provider subscriptions/credentials without cross-user reuse.
- Provide server-derived UserContext for application operations and scoped repositories; prevent caller-supplied owner IDs from establishing authority.
- Encrypt stored credentials with a key supplied outside Git/images and keep credentials out of logs, exports and browser responses.

## Acceptance criteria

- [ ] Two users cannot access each other's accounts or credentials by guessing IDs or altering requests.
- [ ] A user may own multiple broker accounts without conflating account-level positions with virtual lanes.
- [ ] Expired/revoked sessions are rejected; browser write requests have appropriate CSRF protection.
- [ ] Credential updates and deletion/revocation have explicit behaviour and never return plaintext credentials after storage.

## Validation

Integration tests for cross-user reads/writes, session expiry, credential redaction and malicious owner-ID substitution using test credentials only.

## Exclusions

Billing, organisations/teams, social identity providers unless selected as the simplest existing solution, and broker login automation.
