# [FT-02] Freeze the first-slice contracts and golden examples (planning)

GitHub: https://github.com/martyjt/FamilyTrade/issues/3

Planning parent: https://github.com/martyjt/FamilyTrade/issues/1

## Problem

Freeze concrete domain, execution, persistence, recovery and shared UI/MCP contracts
before a lower-cost worker implements the first paper slice. Preserve configurable
strategy behaviour and explicitly chosen paper-model assumptions.

## Current planning packet

- `docs/contracts-v1.md`: entity fields/types, serialization, bars/calendar, builder
  catalogue/equations/bounds, orders/fills/accounting/risk, archive and job crash
  protocols, lane controls/recovery, auth/shared operations and release budgets.
- `docs/contracts-examples-v1.json`: synthetic worked examples and independently
  calculated expected outcomes, not output from the untested prototype.
- `docs/issue-recipes-v1.md`: per-issue contract sections, example requirements,
  exact planned file seams, validation commands and dependency/external gates.
- `docs/bootstrap-packet-v1.md`: file-by-file prototype audit and empty-origin
  bootstrap, with publication authority separated from this planning task.
- `docs/ft02-handoff-v1.md`: precedence, conditional freeze and commissioning boundary.
- `docs/planning-manifest-v1.json` and `docs/ft02-review-v1.md`: exact candidate
  digest, independent final reviews and findings disposition.

The issue publication includes exact artifacts while origin is empty. FT-01 must
publish identical manifest bytes, preserving line endings. A local file path alone
is not a durable GitHub handoff before bootstrap.

## Decisions and defaults

The user requested recommended defaults in this continuation. Adopt the concrete
configurable paper-model defaults in contracts-v1; they are neither claims of
profitability nor actual provider cost/margin quotes. The bounded rule builder,
overnight positions, separate setup/order lifetimes, both paper controls, persistent
manual intent, verified automatic recovery and independent per-user data remain
required. Do not turn a preset into a universal engine restriction.

The original Reversal–Breakout source/default draft and its review hashes remain
unchanged in `docs/strategies/`. Read it with the accepted configurability
clarification and contracts-v1's explicit overrides. Earlier draft placeholders
and issue-history pending-status language are superseded by this packet only after
the final freeze gate. Source defaults do not prove live settings or Pine parity.

## Acceptance and freeze gate

1. All ten named entities specify fields, IDs, types/units, invariants,
   version/serialization rules and rejected input cases.
2. Calendar/completion/correction and indicator/operator rules have one concrete
   meaning; supported trading variations have named modes and bounded parameters.
3. Long/short fills, gap/both-hit/entry-bar behaviour, costs, tick rounding, risk,
   overnight/expiry and open end-state have worked numerical expected outcomes.
4. Archive publication, jobs/fencing/schedules and lanes/control/recovery each have
   explicit state transitions, transaction boundaries and crash/replay examples.
5. Auth/credential denial and shared UI/MCP operations are concrete; release classes,
   numerical budgets, probe windows and rollback are specified.
6. Examples cover two-user denial, same-user independent lanes, pinned correction,
   DST, warm-up/equality, expiry, costs/drawdown and critical crash boundaries.
7. Fresh Reviewer A (Terra/medium) and B (Sol/high) independently inspect the same
   final manifest digest. Resolve material findings and re-review changed packets.
8. Record both final PASS results and exact artifacts in GitHub, verify readback,
   and revise every dependent issue with its concrete recipe. Only then FT-02 is
   PLANNING_COMPLETE and FT-01 READY_FOR_COMMISSIONING.

## Readiness and validation

Current state: **REVIEW_GATED_FREEZE**. This becomes PLANNING_COMPLETE only when
the gate above is satisfied by the linked review/publication evidence.
No Git commit, implementation worktree, CI or code PR is needed to review planning.
Use hand calculations, strict JSON checks, digest checks and independent semantic
review. Do not execute prototype code to generate golden expectations.

Dependencies: none for planning. FT-01 is the first implementation candidate after
freeze. Other issues remain WAIT_DEPENDENCIES, with actual provider/account/server
evidence retained as external requirements. Before each later coding dispatch,
bind planned seams and commands to the integrated baseline and record SHAs.

Worker: Sol/high planning specialist. Reviewer A: Terra/medium. Reviewer B:
Sol/high. Reviews are fresh, read-only contexts and do not reuse the author as an
independent reviewer. The coordinator consolidates the packet; it does not begin
application implementation.

## Exclusions and authority

Application code, migrations, provider adapters, implementation worktrees, commits,
pushes, PRs, merges, VPS changes, purchases, account operations, provider contact and
live orders. No implementation starts in this continuation, even after planning is
ready. The user separately commissions FT-01 under `docs/session-workflow.md`.

Actual IBKR account funding/opening, permissions and Netcup proof remain FT-03 and
later evidence work. COMEX Level 2 is the accepted planning direction; collecting
depth is not authorised here and needs a separate bounded recorder packet.
