## Problem

Backtests need reproducible inputs, durable results and a bounded lifecycle shared by web and MCP clients.

## Dependencies

- https://github.com/martyjt/FamilyTrade/issues/6 — [FT-05] Implement independent candle archives and reproducible dataset revisions
- https://github.com/martyjt/FamilyTrade/issues/7 — [FT-06] Implement validated and versioned strategy definitions
- https://github.com/martyjt/FamilyTrade/issues/8 — [FT-07] Build the deterministic decision and paper-fill engine
- https://github.com/martyjt/FamilyTrade/issues/9 — [FT-08] Implement durable scheduled jobs and bounded worker execution

## Scope

- Implement submit/status/cancel/get-result application operations against pinned strategy and dataset revisions.
- Persist engine/build identity, contract metadata, fee/fill settings, inputs, decisions, fills and terminal state.
- Run simulations in the research worker with bounded memory/CPU and paginated result access.
- Support comparison of explicitly submitted variants while retaining every attempted run; avoid introducing an optimisation framework.

## Acceptance criteria

- [ ] A run ID is returned promptly; a restarted client can retrieve progress/results without holding an HTTP request open.
- [ ] A strategy or dataset correction does not silently change an already submitted run.
- [ ] Two lanes can reuse the same owner's dataset with completely independent simulated balances and outputs.
- [ ] Failed/cancelled runs retain useful diagnostics without presenting partial results as completed.
- [ ] Rerunning pinned inputs reproduces decisions, fills and metrics, and permissions apply to job/result/export access.

## Validation

End-to-end job submission, cancellation/restart, revision pinning, ownership and deterministic rerun tests.

## Exclusions

Unlimited parameter search, live execution, large distributed workers and a user-facing dashboard.
