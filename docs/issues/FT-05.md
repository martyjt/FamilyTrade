## Problem

Each user needs one reliable archive reusable across their lanes, with corrections and archive publication handled without duplicates.

## Dependencies

- https://github.com/martyjt/FamilyTrade/issues/3 — [FT-02] Freeze the first-slice contracts and golden examples (planning)
- https://github.com/martyjt/FamilyTrade/issues/5 — [FT-04] Implement user identity, broker-account ownership and credential storage

## Scope

- Implement PostgreSQL operational storage and per-user Parquet archives with server-generated paths.
- Store current candles and atomically publish completed immutable partitions; define how readers select active versus archived records.
- Enforce owner/source/contract/interval/price-basis keys and preserve finalized/provisional status and data revision manifests.
- Validate OHLC, ticks, ordering and exchange-session gaps; distinguish closed-market intervals from missing data.
- Provide bounded owned-data reads and session-aware aggregation to supported larger candle intervals.

## Acceptance criteria

- [ ] Replaying the same batch creates no duplicate canonical bars; overlapping requests read one record per bar/revision.
- [ ] A correction produces a traceable new revision and completed runs can still load their original revision.
- [ ] A crash between file publication and catalog update has a tested recovery path with no partial partition exposed.
- [ ] Two users have independent files and rows; one user's lanes reuse their owner's archive without additional copies.
- [ ] Normal session closures and DST transitions do not generate false missing-data repairs or misaligned aggregated candles.

## Validation

Database/filesystem integration tests for duplicate batches, corrections, ownership, failed archive publication, session boundaries and restore of a retained dataset manifest.

## Exclusions

Cross-user deduplication, tick/order-book archives, arbitrary continuous-futures adjustment and provider networking.
