## Scope

- Implement a small MCP surface for data coverage, strategy draft/version validation, backtest submit/status/cancel, results/comparisons and paper lane controls.
- Select a supported authenticated remote transport for the VPS and document client setup using current primary documentation.
- Derive ownership from authenticated identity and enforce tool-level permissions, bounded inputs and resource limits on the server.
- Return durable run IDs for long operations and paginated evidence instead of streaming entire archives into model context.

## Acceptance criteria

- [ ] An authenticated client creates a strategy variant, submits a run and retrieves a comparison using the same operations as the UI.
- [ ] Two identities cannot cross-read or cross-control resources, even with crafted tool arguments.
- [ ] Expired/revoked credentials and unsupported scopes fail; secrets are absent from responses and logs.
- [ ] Saved paper lanes continue when the client disconnects; subscription limits and supported client capabilities are documented without promising unlimited AI execution.
- [ ] No arbitrary code execution, raw broker order tool or implicit live activation is exposed.

## Validation

Protocol tests plus an actual supported client round trip with test identities, denial cases, cancellation and reconnect.

## Exclusions

An always-on LLM service, subscription bypass, AI councils, live execution and separate business logic in MCP handlers.

## Accepted paper controls and recovery — 2026-09-12

- Provide both distinct actions: **Pause new entries / keep managing exits**, and
  **Close positions and stop**. The second requests simulated liquidation under the
  reviewed fill model; it cannot report a position closed before an eligible fill.
- Persist operator intent separately from outage/deployment status. Manual pause or
  stop survives reconnect/redeploy and requires an explicit user action to reverse.
- Automatically resume previously running paper lanes only after repaired state,
  verified fresh eligible data and consistency checks. Stay paused with a visible
  reason when recovery fails. Respect sessions and overnight positions.
- Stale/offline feeds cannot produce fabricated current fills. A close-and-stop
  request can remain pending until executable; define handling of existing pending
  entries/exits and later user actions in the FT-02 transition table.
- Historical reconstruction is labelled separately from contemporaneous forward
  evidence. Repeated controls/recovery events cannot duplicate decisions or fills.

Acceptance includes each action with flat/open positions, stale feeds, closed
sessions, reconnects and redeployments. Verify UI and MCP share these operations,
and that a manual pause cannot be overridden by automatic recovery.
